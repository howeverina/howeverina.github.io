## 지킬로 위키를 올릴 때의 강점

이 글은 개인 위키, 혹은 정해진 기여자 5명 내외의 작은 위키를 만든다는 것을 전제로 하고 있습니다. 저의 경우 공부한 것을 직접 정리한다는 컨셉의 위키가 필요했기에, 다른 사람의 기여 내역이 있으면 오히려 마이너스가 될 수 있었습니다. 개인 또는 소규모 위키의 경우 위키 사이트에 들어가서 로그인을 하고 직접 편집창을 보고 편집하는 동적 위키보다는, 저장소를 클론해서 위키 내용을 수정하고 다시 커밋하는 방식의 정적 위키가 편할 수도 있습니다. 위키 편집기가 아무리 좋아봤자 VS Code만 하겠습니까. 게다가 일단 무료니까요. 그리고 이것은 지킬 블로그의 원리와 일맥상통합니다.

따라서 저는 지킬을 기반으로 한 개인 위키 템플릿이 존재할 거라고 생각했고, 그 중 나름 괜찮아 보이는 하나를 찾았습니다.

제가 직접 만들 생각은 안 해 보았냐구요...? 그건... 저는 ruby에 익숙하지 않아서 어렵습니다. Next.js 나 Nuxt.js 로 비슷한 물건을 하나 만들 수 있습니다만 좀더 빠르고 편리한 방법이 있는데 돌아가는 것도 이상하지요.

## 위키 개설 방법

### 지킬 위키 템플릿 - FIRSTwiki

사실을 말하자면 "템플릿" 이 아니라 "이미 사용 중인 위키" 를 포크해 오는 것이기 때문에 상당히 많은 양의 문서와 개인화된 사이트가 따라옵니다. 그래도 이만한 게 없는 것 같아요.

* [FIRSTwiki 레포지토리](https://github.com/firstwiki/wiki)

위 링크를 통해 레포지토리에 방문한 다음 여러분의 계정에 포크해 봅시다. 레포 이름은 그대로 wiki로 괜찮습니다. 다만 이 경우 `username.github.io` 라는 저장소가 이미 있어서 github page로 사용중이어야 하는 걸로 알고 있습니다. 이 저장소에 적당히 블로그라도 하나 올려 둡시다.

### 내용 수정하기

이게 은근히 고역이었습니다. 저는 어제 이걸 하는 데 세 시간 가까이 걸렸는데, 해당 저장소가 좀 오래되었기 때문에 코드도 수정하고 deploy page를 할 때 본래는 원터치로 생성할 수 있는 githb workflow 파일도 수정을 해야 합니다.

심지어 어떤 수정 내역은 뒤쪽 수정 과정을 진행하면서 필요가 없었던 것으로 밝혀진 수정내역이었을 수도 있기 때문에, 깔끔하게 필요한 수정내역만 올려드리기는 어렵습니다. 그래도 최대한 군더더기는 떨쳐내고 필요한 것만 이야기해 보려 합니다.

### (1) 폴더 카피하기

저장소 폴더를 열어주고, 폴더에서 터미널을 열어서 (저는 VS Code에서 터미널을 열어 쓰는 편입니다.)

```bash
cp -r _common/_includes ./_includes
cp -r _common/_layouts ./_layouts
cp -r _common/_data ./_data
```

잘 보시면 저장소 내의 _common 폴더가 타 레포지토리를 참고하는 링크인데, 이런 폴더들은 지킬에서 빌드 시 제외되기 때문에, 이 폴더를 복사해서 로컬 폴더로 만들어 주는 것입니다.

그다음 루트 디렉토리의 `_config.yml` 에서 다음 부분을 주석처리해 줍니다.

```yaml
# includes_dir: _common/_includes
# layouts_dir: _common/_layouts
# data_dir: _common/_data
```

이렇게요. config 파일 수정 하는 김에 사이트 주소, 위키 이름, 위키 설명 등도 전부 수정해 주시는 게 좋아요.

### (2) github pages 배포하기

리포지토리 메뉴 중 맨 오른쪽 Settings - 사이드바의 Pages를 클릭해 주세요. Source에서 Deploy from a branch를 Github actions로 변경해 줍니다. 그러면 지킬 워크플로우 파일을 생성할 수 있도록 될 거예요.

이 워크플로우 파일에서, jobs: 이하를 다음과 같이 수정합니다.

```yml
jobs:
  # Build job
  build:
    runs-on: ubuntu-latest
    env:
      PAGES_REPO_NWO: 깃허브유저네임/저장소이름
    steps:
      - name: Checkout
        uses: actions/checkout@v4
      - name: Setup Ruby
        uses: ruby/setup-ruby@4a9ddd6f338a97768b8006bf671dfbad383215f4
        with:
          ruby-version: '2.7' # Not needed with a .ruby-version file
          bundler-cache: true # runs 'bundle install' and caches installed gems automatically
          cache-version: 0 # Increment this number if you need to re-download cached gems
      - name: Setup Pages
        id: pages
        uses: actions/configure-pages@v5
      - name: Build with Jekyll
        # Outputs to the './_site' directory by default
        run: bundle exec jekyll build
        env:
          JEKYLL_ENV: production
      - name: Upload artifact
        # Automatically uploads an artifact from the './_site' directory by default
        uses: actions/upload-pages-artifact@v3
```

env: 아래 PAGES_REPO_NWO: 를 추가하는 것과 ruby-version: '2.7' 로 내리는 것이 포인트입니다.

이렇게 하고 파일을 생성하면 아마 빌드가 될 겁니다. 하지만 이렇게 해도 안되면, 문의를 한번 남겨주세요. 아니면 챗GPT도 상당한 도움이 되더라구요.
